# 反思：yapi v2.1 实施

## 任务

按 `docs/superpowers/specs/2026-05-24-yapi-v2.1-design.md` 落地 v2.1：`PromptRouter` 升级为 `APIRouter` 的真超集（普通路由直通、prompt 路由收敛到 `.prompt.*` 子命名空间）、参数推断改走 ParamRole + Annotated、PydanticAI 集成类化为 `PydanticAIRunner` + 构造期 warning、删除 v1 残留 `StateStoreError`、新增 `examples/` 与 `tests/test_compat.py` 等三套测试、版本 bump 至 0.2.0、`py.typed` 落库。源码与测试全绿（55 用例），离线 smoke 通过。

## 评估：哪些是结构性结论，哪些是一次性教训

### 结构性、必须固化

**`Annotated` 的稳定内省协议（`get_origin` / `get_args` + `__metadata__` 元组）配合"先匹配先生效"的标记顺序，是 FastAPI 风格签名推断的事实标准做法**——任何后续要在 yapi 上扩展参数语义（比如未来加 `WebSocket`、`StreamingResponse`、自定义 marker）的人，都得遵守同一套结构。最关键的两条 sub-rule：

1. `isinstance(default, params.Body)` 必须在 `isinstance(default, params.Param)` 之前判断。`Body` 与 `Query/Header/Cookie/Path/Form/File` 在 `fastapi.params` 里**不是**父子关系而是兄弟，只有 `Param` 那 6 个走"非 Body 注入"分支；写一个显式 `_INJECTED_FIELD_TYPES` 枚举比依赖 `Param` 基类继承直观且不易在 FastAPI 内部重构后崩。
2. handler 的 `__signature__` 必须**完整保留原始 `Annotated`**（含元数据元组），不能"剥掉 Annotated 留 base type"。FastAPI 的 body / query 解析全靠 Annotated 元信息驱动，剥掉等价于把请求体解析关掉。

这两条是真正的反模式警示，属 reference/ 层（"约束记录"），不是 guide（不是工作流）。

**handler 关键节点的 DEBUG log 在 pytest 下需要 `caplog.at_level("DEBUG", logger="yapi.runtime")` 双指定**才能抓到——只写 `caplog.set_level(logging.DEBUG)` 会因为 root logger 不传播被假绿。这条是测试基建层的隐坑，反复会被踩；属 reference/run-and-test 风格 guide 的一段。

**`PydanticAIRunner` 改成 class 而非 closure 之后，"构造期 warning"成为合法且重要的诊断信号**：未设 `YAPI_MODEL` 的 `PromptRouter()` 会在 `__init__` 阶段发 `YapiUsageWarning`。所有 `examples/*.py` 在 import 时都会触发它——这不是 bug 而是 spec §6.4 明文要求的"真实启动期最早预警"。未来任何"为什么 import example 就有 warning"的疑问都应该被这条规则一句话挡掉，属 must/ 或 reference 层信息。

**v2 → v2.1 的 `.prompt` 子命名空间迁移可以做到"既有 lambda runner 一字不改、调用点只改一字（`.post → .prompt.post`）"**。这次没有写任何破坏性的兼容垫片，靠的是 `_LegacyCallableRunner` 适配层吃下 v2 风格 `lambda **_: {...}`——Protocol 化的新接口和"对 callable 一视同仁"的旧契约可以共存，关键是把适配点放在 runner 层而不是装饰器层。这条策略下一次再做类似 surface 重塑时仍然可复用，属 architecture 层经验。

### 应停在 memory，不必升级

- **`isinstance(payload, endpoint.response_model)` 快路径优化**：顺手的小优化，不构成约束。pydantic v2 即便不加这一行也能正确处理，写在反思里是为了让未来 review 时不要把它误删，不值得进稳定文档。
- **`StateStoreError` 删除前 `rg` 全仓再动手**：spec §6.1 已明文要求，相当于 spec 自己已经把"删 v1 残留先 grep"沉淀过了。再写一遍是冗余。
- **测试矩阵从 15 → 55 用例的具体分布**：每次大改都会变，没有跨任务复用价值。`reference/run-and-test.md` 里的"15 条测试矩阵"原描述本就是过期信息，新数字也不该写死。
- **`monkeypatch + importlib.reload` 跑 example smoke 的具体写法**：复用窗口窄（只在新增 example 模块时才用到），归在 `tests/test_dx.py` 自己作为模板存在就够，不必提升到 guide。

### 灰色地带 — 需要 recorder 拍板

- **`YapiUsageWarning` 的存在与触发条件**应进 `reference/error-catalog.md` 还是 `must/project-shape.md` 的 `YAPI_MODEL` 段？我倾向 must——它是新会话读完 must 就该立刻知道的"为什么有 warning"事实；error-catalog 同步加一条 cross-ref 即可。
- **`Annotated` 内省的两条 sub-rule** 应该是独立的 `reference/annotated-introspection.md` 还是塞进 `architecture/request-lifecycle.md` 的一节？前者更易被精确命中（recorder/未来贡献者搜 "Annotated" 直接命中），后者贴近上下文。我倾向新开短文档。

## 暴露出的真实文档缺口

v2.1 这次实施把 must/ + architecture/ + memory/doc-gaps.md 几乎全部打成过期信息，且至少有两类完全没有对应文档：

1. **must/api-surface.md 还在说"装饰器是 `.get/.post/.put/.patch/.delete`、不能混挂普通 FastAPI 接口"**——这两条断言在 v2.1 之后**双双失效**：现在是 `router.prompt.post`，且普通 `router.get` 走 APIRouter 原生通道，混挂被官方允许甚至鼓励（见 `examples/mixed_router.py`）。这是 must 层最严重的事实漂移，必须最高优先级修。
2. **must/project-shape.md "公开符号只有 `PromptRouter` 一个、源码 ~280 行"** 同样过期：`yapi/__init__.py` 现在 re-export 7 个符号（含 `PydanticAIRunner` / `YapiUsageWarning` / `RunnerContext` 等），源码体量翻倍。
3. **architecture/request-lifecycle.md 与 architecture/agent-runner-contract.md** 仍按 v2 的 closure runner + 单一 BaseModel 参数描述；ParamRole 多分类、Annotated 全面化、PydanticAIRunner 类化、RunnerContext 注入 prompt_composer 这几条事实在文档里**完全缺席**。
4. **doc-gaps.md 第一条 "`architecture/agent-runner-contract.md` 文件不存在"** 仍然成立——上一次 PyPI bootstrap 反思就标出过这洞，至今没补；v2.1 让这洞从"缺一份"变成"缺两份"（runner 契约 + 新增的 ParamRole 推断契约）。
5. **`reference/` 目录至今为空**——上一次反思把 release.md 落到了 guides/，但 v2.1 引入的两类"约束记录"（Annotated 协议、caplog 双指定、YapiUsageWarning 触发条件）非常典型地属于 reference 层。继续放空是欠债。

## 流程层面的元教训

**这一轮唯一值得标记的"过程经验"是：实施前用一次性最小脚本验证标准库行为（`get_origin / get_args` 对 `Annotated[int, "x"]` 的具体返回）比反复读 typing PEP 文档高效**。把"标准库到底返回什么"作为可执行事实拿到手里，再去写分类函数，避免了在 `_classify_param` 里散落 trial-and-error。这条不进任何稳定文档（属个人工作风格），但值得在反思里留一笔——下次再遇"跨版本类型 introspection"时直接复用这个动作。

另外，**`StateStoreError` 删除、`yapi/__init__.py` re-export、`pyproject.toml` 版本 bump、`py.typed` 落库这四件事被打进同一轮实施**，从 git 史可读性看是不理想的——和上次 PyPI bootstrap 的 `307836a` 同病。但和上次一样，这次也是 release-bootstrap 性质的不可分原子操作（删 v1 残留 + 暴露 v2.1 公开符号 + 标 0.2.0 + 标 typed 是同一件事），事后回看依旧没法干净拆分。这条不进文档，只在这里第二次留存——如果第三次再出现，应该升级为 must/ 或 guide 层的"何时允许 bootstrap-style 大 commit"。

## Promotion Candidates（给 recorder 的清单）

按优先级排序，每条写明"去哪 / 为什么去那里"。

1. **must/api-surface.md（整段重写，不新开文件）**
   把"覆盖 5 个装饰器 / 不能混挂普通 FastAPI 接口"两条断言改为：`PromptRouter` 是 `APIRouter` 真超集，普通路由直通；prompt 路由收敛到 `router.prompt.{get,post,put,patch,delete}` 子命名空间；同 router 内 prompt + 普通混挂被官方支持。同时把"最多一个 BaseModel 参数"的描述改成 ParamRole 多分类 + Annotated 全面化的事实表述。
   *理由*：v2.1 之后 must 层最严重的事实漂移；不修，新会话读完 must 会写错代码。

2. **must/project-shape.md（修两处事实 + 加一段）**
   (a) "公开符号只有 `PromptRouter` 一个" → 改为 7 个 re-export（列出 `PromptRouter` / `PydanticAIRunner` / `RunnerContext` / `YapiUsageWarning` / `YapiDeclarationError` / `RuntimeExecutionError` / `YapiError`）。(b) "源码 ~280 行"删掉或更新。(c) `YAPI_MODEL` 段追加一行：未设 `YAPI_MODEL` 的 `PromptRouter()` 会在**构造期**发 `YapiUsageWarning`，所有 example 模块 import 时触发该 warning 是 spec §6.4 要求的预期行为，不要静音。
   *理由*：(a)(b) 是事实漂移；(c) 永久回答"为什么 import example 就有 warning"。

3. **reference/annotated-introspection.md（新建短文）**
