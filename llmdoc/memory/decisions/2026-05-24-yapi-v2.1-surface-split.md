# 决策：v2.1 装饰器表面拆分

**决策**：`PromptRouter` 不再覆盖 `APIRouter` 的 `.get/.post/.put/.patch/.delete`；prompt 路由收敛到显式 `router.prompt.<method>` 子命名空间；同时保留 `_LegacyCallableRunner` 适配 v2 风格 4-keyword callable，**不**发 deprecation 警告。

## 上下文（三行）

- v2 让 `.post = prompt` 是 surprising default：真实项目几乎都需要健康检查 / metrics / CRUD 与 prompt 路由共存，强制新开 router 是 boilerplate；这同时让 `PromptRouter` 失去"FastAPI 自然扩展"的口号站点。
- 候选方案中只有"子命名空间 `.prompt.*`"既能与 FastAPI method 风格保持同层级，又能给未来扩展（`.prompt.stream` 等）留扩展位（spec §3.2）。
- `_LegacyCallableRunner` 是低成本兼容垫片（不到 10 行），让 v2 测试 / 用户代码里的 `agent_runner=lambda **_: {...}` 一字不改继续工作；v2.1 的 surface 已经够大破坏量，不需要在 runner 维度再加一道 deprecation 噪音。

## 如果未来有人提议"统一回 `router.post` / 删 legacy adapter"

- "回 `router.post = prompt`" 会重新让 `PromptRouter` 失去 superset 身份，重新引入 v2 的混挂痛点；需先证明 superset 假设错了。
- 删 `_LegacyCallableRunner` 等价于强制下游迁到 class runner / Protocol；垫片成本极低（< 10 行），删除前需有量化证据（如垫片导致 bug、维护成本超过收益）。
