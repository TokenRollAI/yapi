## 1. 本次设计的动机

v2 把 API 收紧到「FastAPI 的 `.post` + 一个有 docstring 的函数」之后，框架表面体积压到 ~280 行。但在最近的回顾与审稿过程中，暴露出三类问题：

**A. `PromptRouter` 与 `APIRouter` 的关系是"覆盖"，不是"扩展"**

- v2 显式覆盖了 `.get/.post/.put/.patch/.delete`，把所有 HTTP 方法都强制变成 prompt 路由。
- 这让 `PromptRouter` **看起来**继承自 `APIRouter`，**用起来**却是一个完全不同的东西：同一个 router 内不能同时挂普通 FastAPI 接口与 prompt 接口；想混挂必须新开一个 `APIRouter`。
- 真实项目里很少有纯 prompt 服务——绝大多数 LLM 接口需要配套的健康检查、metrics、CRUD、回调、Webhook 等普通 FastAPI 路由。强制两个 router 实例让用户写更多 boilerplate，并且让 `PromptRouter` 失去了"FastAPI 自然扩展"的口号站点。

**B. 与 FastAPI 的兼容性还有"撕裂感"**

- 装饰器签名是 `post(self, path: str, **_unused)`，FastAPI 原生 kwargs（`tags=` / `summary=` / `status_code=` / `description=` / ...）全部进 `_unused` 被静默丢弃。开发者写 `@router.post("/wish", tags=["wishes"])`，OpenAPI 里看不到 tag，也不会有任何提示——这是 llmdoc 已经登记的开发者陷阱。
- `async def` 用户函数会在请求期落入「非 str 非 None」守卫，HTTP 500 错误指向"返回类型不对"，错误信息和真实原因脱节。
- 函数签名内省只认裸 `BaseModel` 参数与 `Depends(...)` 默认值，不认 FastAPI 原生的 `Annotated[WishIn, Body(...)]` / `Annotated[str, Query(...)]` / `q: str = Header(...)` 这类风格。

**C. 框架对外缺少"可观测性"与"扩展点"**

- `agent_runner` 是个朴素 `Callable`，丢失了 `path / method / endpoint` 等元信息。用户自定义 runner 想做 tracing / token counting / 基于 path 的分支，没有任何 hook。
- 默认 runner 把所有异常压成 `RuntimeExecutionError("Agent execution failed")`，原始 traceback 只能通过 `__cause__` 看到，错误体不带任何 hint。
- 整个请求期完全黑盒，没有任何 `logging` 输出。

**D. 文档与发布形态有"对外可见的断面"**

- README 是英文，但 `examples/wish_api.py` 与 llmdoc 整套都是中文。
- `examples/` 只有一个空 docstring 的 `wish_api.py`，连 `Depends` / 动态 prompt 都没演示过。
- `errors.py::StateStoreError` 是 v1 残留；`yapi/agent.py` 的 `DEFAULT_SYSTEM_PREFIX` 是死代码（详见 `llmdoc/architecture/request-lifecycle.md` §3.4）。

v2.1 的目标是把 A 当作核心方向调整，B/C/D 当作配套补齐。

## 2. v2.1 设计原则

继承 v2 全部原则，并新增 5 条：

1. **`PromptRouter` 是 `APIRouter` 的 superset，不是替代**：所有 FastAPI 原生写法在 `PromptRouter` 上必须直接可用；prompt 路由通过显式入口标识。
2. **声明体验越来越像原生 FastAPI**：函数签名识别原生 FastAPI 写法（`Annotated[...]` / `Depends` / kwargs）；开发者从 FastAPI 切到 yapi 时复用既有习惯。
3. **静默丢弃是反模式**：能透传的透传，不能透传的显式 warning 或装饰期报错，任何 yapi 不打算支持的 FastAPI kwarg 都让开发者知道。
4. **请求期不再是黑盒**：关键节点有 `logging`，错误信息携带足够 debug 上下文。
5. **`agent_runner` 是一等扩展点**：从「朴素 callable」抬升为「显式 Protocol + 上下文对象」，方便用户接入 tracing / 多模型路由；Protocol 只用于结构提示，运行期校验仍由测试覆盖。

## 3. PromptRouter 兼容 APIRouter

这是 v2.1 最大的方向变更。**v2 的"`.get/.post/.put/.patch/.delete` 全部被覆盖为 prompt 路由"在本版本被显式收回**。

### 3.1 行为转变

| 调用 | v2 行为 | v2.1 行为 |
|---|---|---|
| `router.get("/x")` | prompt 路由 | **原生 FastAPI 路由**（恢复 APIRouter 默认） |
| `router.post("/x")` | prompt 路由 | **原生 FastAPI 路由** |
| `router.put / patch / delete` | prompt 路由 | **原生 FastAPI 路由** |
| `router.prompt.get / post / put / patch / delete` | 不存在 | **prompt 路由**（v2 的 `.get/.post/...` 等效物） |

这意味着：

- `PromptRouter` 实例可以直接当 `APIRouter` 用，所有 FastAPI 习惯（`tags=` / `Depends` / `response_model=` / 中间件）原样工作。
- 想声明 prompt 路由，必须显式写 `@router.prompt.post(...)`。
- 一个 `PromptRouter` 内可以同时挂普通 FastAPI 路由与 prompt 路由。

### 3.2 设计选择：子命名空间 `router.prompt.*`

候选方案：

| 方案 | 形态 | 优点 | 缺点 |
|---|---|---|---|
| **A. 子命名空间（采用）** | `@router.prompt.post("/x")` | 与 `.post / .get` 同层级 method 风格一致；命名清楚；未来可扩展 `.prompt.stream` 等 | 多一层属性访问 |
| B. 单一装饰器 + method 参数 | `@router.prompt("/x", method="POST")` | 平坦 | 与 FastAPI 风格不一致；method 写在 kwarg 里反直觉 |
| C. v1 风格函数名 | `@router.llm_post("/x")` | 平坦 | 与 v2 主动放弃的 `llm_*` 命名冲突 |
| D. 全局装饰器 | `@prompt_route(method, path)` | 与 router 解耦 | 拿不到 `_runtime`，需要全局注册 |

采用 **A**。

### 3.3 `router.prompt` 是什么

`router.prompt` 是 `PromptRouter` 实例上的一个属性，返回一个 `_PromptDecorators` 辅助对象：

```python
class _PromptDecorators:
    def __init__(self, router: "PromptRouter") -> None:
        self._router = router

    def get(self, path: str, **kwargs):    return self._router._register_prompt("GET", path, **kwargs)
    def post(self, path: str, **kwargs):   return self._router._register_prompt("POST", path, **kwargs)
    def put(self, path: str, **kwargs):    return self._router._register_prompt("PUT", path, **kwargs)
    def patch(self, path: str, **kwargs):  return self._router._register_prompt("PATCH", path, **kwargs)
    def delete(self, path: str, **kwargs): return self._router._register_prompt("DELETE", path, **kwargs)


class PromptRouter(APIRouter):
    def __init__(
        self,
        agent_runner: "AgentRunner | None" = None,
        prompt_composer: "PromptComposer | None" = None,
        **apirouter_kwargs,
    ) -> None:
        super().__init__(**apirouter_kwargs)  # 透传 APIRouter 全部 kwargs
        self._runtime = Runtime(
            agent_runner=_coerce_runner(agent_runner or build_default_runner()),
            prompt_composer=prompt_composer or compose_prompt,
        )
        self.prompt = _PromptDecorators(self)

    # 注意：不再覆盖 .get / .post / .put / .patch / .delete
```

注意点：

- `PromptRouter.__init__` 接受 `**apirouter_kwargs` 并 `super().__init__(**apirouter_kwargs)`：用户可以传 `prefix=` / `tags=` / `dependencies=` 等 APIRouter 原生构造参数。
- `self.prompt` 是普通实例属性，不是子 router。`router.prompt.post("/x")` 注册的路由仍然落到 `router.routes` 上，`app.include_router(router)` 会同时包含原生路由与 prompt 路由。

### 3.4 混挂示例

```python
from fastapi import FastAPI, Depends
from pydantic import BaseModel
from yapi import PromptRouter

class WishIn(BaseModel):
    user_id: str
    wish: str

class WishOut(BaseModel):
    """你是一个愿望受理实体。请返回结构化结果。"""
    granted: bool
    message: str

router = PromptRouter(prefix="/v1", tags=["wishes"])

# 普通 FastAPI 路由
@router.get("/health")
def health() -> dict:
    return {"status": "ok"}

# Prompt 路由
@router.prompt.post("/wish")
def make_a_wish(req: WishIn) -> WishOut:
    """根据用户的愿望决定是否实现。"""

app = FastAPI()
app.include_router(router)
```

`GET /v1/health` 走原生 FastAPI；`POST /v1/wish` 走 prompt 管线。两者共享 router 的 `prefix=` 与 `tags=`。

### 3.5 边界与不变量

- `router.get/.post/...`：纯粹的 `APIRouter` 行为，不经过 yapi 的任何内省。
- `router.prompt.get/.post/...`：v2 的 `_introspect` + handler 闭包 + `Runtime.execute` 链路在此分支内完整保留，全部约束（返回注解必须是 BaseModel 子类、最多一个 BaseModel 参数、函数返回 None/str、…）原样生效。
- `router.prompt` 不持有独立 routes 集合，所有路由都注册到 `router.routes`，OpenAPI 中正常显示。
- `PromptRouter(prefix=..., dependencies=..., ...)` 这些 APIRouter 原生 kwargs 同时影响原生路由与 prompt 路由——这是有意为之，让 prompt 路由享受 router 级别的统一配置。

### 3.6 与 v2 的破坏关系

v2 的 `@router.post("/wish")` = prompt 路由 → v2.1 中变为**原生 FastAPI POST 路由**。这是显式的、有意的破坏。理由：

- 不破坏的话，`PromptRouter` 无法真正成为 `APIRouter` superset。
- 当前用户群很小（包刚发到 PyPI，对外 contributors 为零），迁移成本可控。
- 迁移规则极简：`router.post(...)` → `router.prompt.post(...)`，机械替换，工具辅助即可。

详细迁移说明见 §9.2。

## 4. FastAPI 兼容性升级

本节描述的所有规则**只作用于 `router.prompt.*` 子命名空间**——它是 v2 `_introspect` / handler 链路的升级版。原生 `.get/.post/...` 走纯 FastAPI，本节不涉及。

### 4.1 安全 kwargs 透传白名单

`router.prompt.<method>(path, **kwargs)` 的 kwarg 处理规则：

#### 透传白名单

下列 kwarg 直接透传给底层 `add_api_route`：

| kwarg | 说明 |
|---|---|
| `tags` | 透传，进入 OpenAPI |
| `summary` | 透传，进入 OpenAPI |
| `description` | 透传，进入 OpenAPI |
| `status_code` | 透传，覆盖默认 200 |
| `deprecated` | 透传，进入 OpenAPI |
| `operation_id` | 透传，覆盖自动 operation_id |
| `name` | 透传，影响 `url_for` |
| `include_in_schema` | 透传，是否出现在 OpenAPI |
| `responses` | 透传，扩展 OpenAPI responses 定义 |
| `openapi_extra` | 透传，注入额外 OpenAPI 字段 |

#### 拒绝清单（装饰期 `YapiDeclarationError`）

| kwarg | 拒绝原因 |
|---|---|
| `response_model=` | 与「返回注解推断」冲突；让 prompt 端与序列化端使用两个不同模型 |
| `response_class=` | yapi 自己控制响应输出形态 |
| `dependencies=` | FastAPI 层级依赖会绕过 `Runtime` 的 `injected` 通道，破坏「`request` 与 `injected` 是两条独立数据通道」不变量；用户应该写到函数签名上以 `Depends(...)` 形式 |

#### 其他未识别 kwarg：`YapiUsageWarning`

非白名单、非拒绝清单中的 kwarg 走 `warnings.warn(..., category=YapiUsageWarning, stacklevel=3)`。消息形如 `yapi: kwargs ['xxx'] are not recognized and will be ignored`。

理由：

- 静默吞错是 v2 已知陷阱，必须替换。
- 直接抛错会破坏迁移路径（FastAPI 老用户习惯性写各种 kwarg）。
- `warnings.warn` 在默认 stderr 与 pytest 都会展示，能在不破坏迁移的前提下让陷阱浮出水面。

`YapiUsageWarning` 继承 `UserWarning`，在 `yapi/errors.py` 中定义并在 `yapi/__init__.py` 中 re-export（见 §6.1）。

### 4.2 async def 路由函数支持

#### 契约

- `router.prompt.*` 装饰的函数允许是 `def` 或 `async def`。
- `def` 时 handler 内 `dynamic_prompt = func(**kwargs)`（保持 v2 行为）。
- `async def` 时 handler 内 `dynamic_prompt = await func(**kwargs)`。
- 返回值仍只能是 `None` 或 `str`，类型守卫照旧。

#### 实现位置

`yapi/router.py` 装饰器构造 handler 时，用 `inspect.iscoroutinefunction(func)` 分支：

```python
is_async = inspect.iscoroutinefunction(func)

async def handler(**kwargs):
    injected, request_instance = _split_kwargs(kwargs, param_roles, request_param_name)

    if is_async:
        dynamic_prompt = await func(**kwargs)
    else:
        dynamic_prompt = func(**kwargs)

    if dynamic_prompt is not None and not isinstance(dynamic_prompt, str):
        raise RuntimeExecutionError(
            f"yapi prompt route '{func.__name__}' must return None or str, "
            f"got {type(dynamic_prompt).__name__}"
        )
    ...
```

#### 边界

- 用户函数内部 `await` 抛错（如 `httpx.ConnectError`）会**直接向上冒**，不被 `RuntimeExecutionError` 包装。理由：动态 prompt 计算发生在 `Runtime.execute` 之前的 handler 层，错误属于"用户代码错误"，让 FastAPI 默认 500 处理 + traceback 保持干净。
- 同步 `def` 用户函数不会被引入新的线程池层；它仍在 handler 的事件循环内同步求值（与 v2 一致）。
- 生成器 / 异步生成器（`def f(): yield x` / `async def f(): yield x`）不在支持范围：`inspect.isgeneratorfunction(func)` / `inspect.isasyncgenfunction(func)` 为真时装饰期抛 `YapiDeclarationError`，提示"prompt route must return None or a str, not a generator"。

### 4.3 Annotated[Body/Query/Header/Cookie/File/Form] 参数解析

v2 的 `_introspect` 只认两种参数：

1. `default` 是 `fastapi.params.Depends`
2. `annotation` 是 `BaseModel` 子类

v2.1 扩展为认得 FastAPI 原生参数形态，并保持「最多一个请求体来源」核心契约。

#### 4.3.1 参数形态分类规则

按以下顺序分类，先匹配先生效：

```
读 param.default
  └─ 是 fastapi.params.Depends 实例 → DEPENDENCY
  └─ 是 fastapi.params.{Query,Header,Cookie,Path,Form,File} 实例 → INJECTED_FIELD
  └─ 是 fastapi.params.Body 实例
       └─ annotation（去 Annotated 外层后）是 BaseModel 子类 → REQUEST_MODEL
       └─ 否则 → 装饰期 YapiDeclarationError（见 §4.3.3）
  └─ 否则 → 读 annotation
读 annotation
  └─ get_origin(annotation) is Annotated:
       提取 metadata，按顺序找到第一个 fastapi.params.* 标记 → 按 default 同样规则分类
       没有 FastAPI 标记 → 用 base type 继续走"否则"分支
  └─ 是 BaseModel 子类 → REQUEST_MODEL
  └─ 否则 → 装饰期 YapiDeclarationError（明确禁止 FastAPI 隐式 Query 推断）
```

分类结果落在一个 `dict[str, ParamRole]` 上：

```python
class ParamRole(Enum):
    REQUEST_MODEL = "request_model"
    DEPENDENCY = "dependency"
    INJECTED_FIELD = "injected_field"   # Query/Header/Cookie/Path/Form/File
```

#### 4.3.2 handler 内参数分流

```python
async def handler(**kwargs):
    injected = {}
    request_instance = None
    for name, role in param_roles.items():
        if name not in kwargs:
            continue
        if role is ParamRole.REQUEST_MODEL:
            request_instance = kwargs[name]
        else:
            injected[name] = kwargs[name]
    ...
```

也就是说，所有 `DEPENDENCY` / `INJECTED_FIELD` 参数都进 `injected`，agent_runner 看到的 `injected` 形如 `{"profile": {...}, "x_token": "abc", "page": 2}`。

#### 4.3.3 拒绝的形态（装饰期 YapiDeclarationError）

| 形态 | 拒绝原因 |
|---|---|
| 两个 BaseModel 参数（含 `Annotated[T, Body(...)]`） | v2 "最多一个 request_model" 契约 |
| `q: str` 裸写 / `q: int = 0` | 明确禁止 FastAPI 隐式 Query 推断；要求显式 `Annotated[str, Query()]` 或 `= Query(...)` |
| `q: str = Body(...)` 或 `Annotated[str, Body(...)]`（非 BaseModel + Body） | request_model 的语义锚点是 BaseModel docstring；标量 Body 会让 prompt 拼装失去稳定锚点。**拒绝**，要求开发者用 `Annotated[str, Query()/Header()/...]` 表达 |
| 多个 `Annotated[T, Body(embed=True)]` 字段 | 同上，多 Body 让 prompt 拼装失去锚点。仍然「最多一个 request_model」 |
| `*args` / `**kwargs` | 保留 v2 拒绝行为 |

#### 4.3.4 handler `__signature__` 修补规则

这一条是审稿反馈点的硬约束：**handler 的 `__signature__` 必须原样保留用户函数的 `inspect.Parameter`，不能把 `Annotated[T, marker]` 规整成 `T`，也不能丢掉 `default`**。

理由：

- FastAPI 通过 `__signature__` 内省请求体、依赖、参数标记；丢掉 `Annotated` 或 `default` 都会让 FastAPI 解析失败。
- v2 当前 `handler.__signature__ = inspect.Signature(parameters=handler_params, return_annotation=response_model)` 直接复用了 `inspect.signature(func).parameters` 的原始 `Parameter`，恰好满足这一约束。v2.1 必须延续这一做法。

`yapi/router.py` 内的实现：

```python
import inspect

original_signature = inspect.signature(func)
handler.__signature__ = inspect.Signature(
    parameters=list(original_signature.parameters.values()),  # 原样
    return_annotation=response_model,
)
handler.__annotations__ = {
    p.name: p.annotation
    for p in original_signature.parameters.values()
    if p.annotation is not inspect.Parameter.empty
}
handler.__annotations__["return"] = response_model
handler.__name__ = func.__name__
```

`param_roles` 与 `request_param_name` 的解析是 yapi **内部状态**，**不**反映在 `handler.__signature__` 上——FastAPI 看到的依然是原签名，yapi 看到的是分类结果。两套视图各管各的。

#### 4.3.5 接受的形态总览

| 形态 | 角色 | 备注 |
|---|---|---|
| `req: WishIn` | REQUEST_MODEL | v2 已支持 |
| `req: Annotated[WishIn, Body(...)]` | REQUEST_MODEL | 新；FastAPI 元信息透传 |
| `req: Annotated[WishIn, Body(embed=True)]` | REQUEST_MODEL | 新；`embed=True` 由 FastAPI 处理 |
| `dep = Depends(get_db)` | DEPENDENCY | v2 已支持 |
| `dep: SomeType = Depends(get_db)` | DEPENDENCY | v2 已支持 |
| `dep: Annotated[SomeType, Depends(get_db)]` | DEPENDENCY | 新 |
| `q: Annotated[str, Query()]` | INJECTED_FIELD | 新 |
| `q: str = Query(...)` | INJECTED_FIELD | 新 |
| `x_token: Annotated[str, Header()]` | INJECTED_FIELD | 新 |
| `c: Annotated[str, Cookie()]` | INJECTED_FIELD | 新 |
| `file: Annotated[UploadFile, File()]` | INJECTED_FIELD | 新 |
| `form: Annotated[str, Form()]` | INJECTED_FIELD | 新 |
| `id: Annotated[str, Path()]` | INJECTED_FIELD | 新（路径参数也走 injected） |

## 5. agent_runner Protocol 化

把 v2 的 `Callable[..., dict]` 抬升为显式 Protocol + Context 对象，给用户自定义 runner 一个稳定的扩展面。

### 5.1 v2 现状回顾

v2 runner 契约：

```python
def runner(*, prompt: str, request: dict, injected: dict, response_model: type[BaseModel]) -> dict: ...
```

问题：

- `path` / `method` / `endpoint` 完全不可见，无法做基于 path 的分支、tracing、metrics tag。
- 没有形式化类型，自定义 runner 漏参数只能在运行期 `TypeError`。

### 5.2 v2.1 契约

新增 `yapi/runner.py`：

```python
from typing import Protocol, runtime_checkable
from dataclasses import dataclass
from pydantic import BaseModel

@dataclass(frozen=True)
class RunnerContext:
    prompt: str
    request: dict
    injected: dict
    response_model: type[BaseModel]
    path: str
    method: str


@runtime_checkable
class AgentRunner(Protocol):
    def run(self, ctx: RunnerContext) -> dict | BaseModel:
        """同步调用，返回 dict（会被 model_validate）或 BaseModel 实例。"""
        ...
```

`PromptRouter.__init__` 改为：

```python
def __init__(
    self,
    agent_runner: AgentRunner | None = None,
    prompt_composer: PromptComposer | None = None,
    **apirouter_kwargs,
) -> None:
    ...
```

### 5.3 Protocol 兼容性的局限

审稿点指出：`@runtime_checkable` Protocol 的 `isinstance` 检查只做**浅层结构匹配**——只要对象有 `run` 属性即通过，不校验签名。一个有 `run` 属性但签名错的对象会在请求期才炸。

设计立场：

- Protocol 在 v2.1 中**只承担"类型提示"职责**：让用户在写自定义 runner 时享受 IDE / mypy / pyright 的静态提示，而不是承担"运行期保险"职责。
- 真正的运行期保险靠测试矩阵覆盖（§8.3 `test_bad_runner_raises_at_request_time`）。
- 错误消息升级（§6.3）保证 runner 内部异常的 traceback 不丢失，让"运行期才炸"的调试代价可接受。

文案上避免说"Protocol 解决了运行期 TypeError 问题"，改为"Protocol 提供了静态结构提示与运行期的最小契约校验"。

### 5.4 向后兼容：朴素 callable 仍然能用

为了让 v2 的 `lambda **_: {...}` 写法不破坏，`Runtime` 在初始化时通过 `_coerce_runner` 适配：

```python
def _coerce_runner(runner) -> AgentRunner:
    if hasattr(runner, "run") and not isinstance(runner, type):
        return runner  # 鸭子类型，覆盖类实例与 Protocol-conforming 对象
    if callable(runner):
        return _LegacyCallableRunner(runner)
    raise TypeError(
        f"agent_runner must be an AgentRunner or a (*, prompt, request, injected, response_model) callable, "
        f"got {type(runner).__name__}"
    )

class _LegacyCallableRunner:
    def __init__(self, fn): self._fn = fn
    def run(self, ctx: RunnerContext):
        return self._fn(
            prompt=ctx.prompt,
            request=ctx.request,
            injected=ctx.injected,
            response_model=ctx.response_model,
        )
```

效果：

- v2 测试里的 `agent_runner=lambda **_: {...}` 写法继续工作。
- 自定义 class runner 也直接工作（鸭子类型 + Protocol 注解）。

### 5.5 默认 runner 重写

`yapi/agent.py` 的默认 runner 工厂从函数闭包改为类：

```python
class PydanticAIRunner:
    def __init__(self, model: str | None = None) -> None:
        self._model = model or os.getenv("YAPI_MODEL")

    def run(self, ctx: RunnerContext) -> dict:
        if self._model is None:
            raise RuntimeError(
                "YAPI_MODEL is not set. "
                "Set YAPI_MODEL=test for an offline smoke test, "
                "or YAPI_MODEL=openai:gpt-4o etc. for real models."
            )
        agent = Agent(self._model, output_type=ctx.response_model, system_prompt=ctx.prompt)
        result = agent.run_sync(f"request={ctx.request}\ninjected={ctx.injected}")
        output = getattr(result, "output", result)
        return output.model_dump() if hasattr(output, "model_dump") else dict(output)
```

旧的 `build_agent_runner()` 保留为 thin wrapper，返回 `PydanticAIRunner` 实例：

```python
def build_default_runner(model: str | None = None) -> AgentRunner:
    return PydanticAIRunner(model=model)

# 兼容 v2 名字
build_agent_runner = build_default_runner
```

### 6.4 默认 runner 构造期 warning

审稿点：v2.1 草案把这条说成 "import-time warning" 不准确——warning 真正发生在 `build_default_runner()` 被调用的时刻（即 `PromptRouter()` 不传 `agent_runner` 时）。措辞收窄如下：

- 触发时机：**`build_default_runner()` 调用时**（典型场景：`PromptRouter()` 构造期，且未显式传 `agent_runner=`）。
- 触发条件：`model` 参数为 None **且** `os.environ["YAPI_MODEL"]` 未设置。
- 不触发的场景：用户传了 `agent_runner=<my_runner>`；`YAPI_MODEL` 已设置；显式调用 `build_default_runner(model="...")`。

实现：

```python
def build_default_runner(model: str | None = None) -> AgentRunner:
    resolved = model or os.getenv("YAPI_MODEL")
    if resolved is None:
        warnings.warn(
            "YAPI_MODEL not set; the first request to a prompt route will raise. "
            "Set YAPI_MODEL=test for an offline smoke test, "
            "or YAPI_MODEL=openai:gpt-4o etc. for real models.",
            YapiUsageWarning,
            stacklevel=2,
        )
    return PydanticAIRunner(model=resolved)
```

测试场景如何静音：

- 单元测试普遍使用 `PromptRouter(agent_runner=lambda **_: {...})`，构造期不会进 `build_default_runner` 分支，warning 不会出现。
- 端到端 smoke 测试期望使用 `YAPI_MODEL=test`，warning 也不出现。
- 真实启动忘记 `YAPI_MODEL` 时 warning 是预期信号，不静音是正确行为。

## 9. 迁移与兼容性

### 9.1 兼容部分

- `from yapi import PromptRouter`：**不变**。
- `PromptRouter()` 无参数构造：**不变**（默认 runner 工厂沿用旧名 `build_agent_runner = build_default_runner`）。
- `agent_runner=lambda **_: {...}` 风格注入：**仍然能用**（通过 `_LegacyCallableRunner` 适配）。
- `Runtime.execute` 对外签名：**保持**（内部走 `RunnerContext` 是实现细节）。
- `compose_prompt` 默认行为：**保持**。
- llmdoc 中所有 v2 documented contract（最多一个 BaseModel 参数 / 函数返回 None|str / `_introspect` 错误分支）：**保持**，仅作用域从"`.post/.get` 默认行为"变成"`.prompt.*` 子命名空间"。

### 9.2 破坏部分

| 破坏点 | v2 行为 | v2.1 行为 | 迁移 |
|---|---|---|---|
| `@router.post("/x")` 注册 prompt 路由 | 是 | **否，变为原生 FastAPI POST** | 改写为 `@router.prompt.post("/x")` |
| `@router.get/.put/.patch/.delete` 同上 | 是 | **否** | 同上 |
| `@router.post("/x", response_model=Foo)` 静默丢弃 | 是 | **装饰期 `YapiDeclarationError`** | 删除该 kwarg（response_model 来自函数返回注解） |
| `@router.post("/x", dependencies=[...])` 静默丢弃 | 是 | **装饰期 `YapiDeclarationError`** | 把 dependencies 写到函数参数上以 `Depends(...)` 形式 |
| `from yapi.errors import StateStoreError` | 成功（v1 残留） | **`ImportError`** | 删除引用（实际无人使用） |
| `async def make_a_wish(...) -> WishOut: ...` 必失败 | 是（HTTP 500） | **成功** | 反向兼容，无需迁移 |
| `q: str` 裸参数 | 装饰期失败 | 装饰期失败（错误消息更清晰） | 改为 `Annotated[str, Query()]` |

### 9.3 版本号

按审稿建议，**不**用 SemVer MAJOR 论证。立场如下：

- 项目仍在 `0.x` 期，按 SemVer 约定 `0.x.y` 中 `MINOR` 增量允许引入破坏性变更。
- v2.1 引入的破坏点都属于"把 v2 的暗坑显性化为早失败"——`@router.post = prompt` 是 v2 的 surprising default；静默吞 kwarg 是登记在 doc-gaps 的陷阱。
- 因此版本号选择 `0.1.0` → **`0.2.0`**，PR 描述里点名上面 9.2 表的所有破坏点，配套迁移说明放进 README 与 CHANGELOG。

发布流程沿用 `llmdoc/guides/release.md` 已有的 tag-driven 流程。

## 10. 明确不做的事

- **不做流式响应**：根据用户决策，流式作为业务逻辑层的事情，不进入框架核心；NDJSON / SSE / WebSocket / binary stream 全部留给应用层自行处理（可以基于 FastAPI 原生 `StreamingResponse` 在 `@router.get/.post` 原生路由上实现）。
- 不重新引入 v1 的 `state_*` 参数到装饰器；state 延续 v2 决定。
- 不引入装饰器层的 retry / timeout / cache hook（留给 v2.2 或更晚）。
- 不做 prompt injection 缓解（用户决策）。
- 不引入 NDJSON、WebSocket、binary frame 等 wire 形式。
- 不为流式与非流式提供两套装饰器：差异通过显式入口（`.prompt.*` vs `.get/.post`）表达。
- 不重写 `Runtime.execute` 的对外签名：保持现状以最小化下游冲击。
- 不在 v2.1 落实 CI lint / format / mypy 强校验；这些独立 PR 推进。
- 不在 v2.1 写 CHANGELOG / CONTRIBUTING（单独安排）。

## 11. 一句话总结

`yapi` v2.1 让 `PromptRouter` 真正成为 `APIRouter` 的 superset——`.get/.post/...` 恢复 FastAPI 原生行为、prompt 路由进入 `.prompt.*` 子命名空间；同时在 `.prompt.*` 内部把 FastAPI 写法（透传 kwargs / `async def` / `Annotated[...]`）补齐，把 `agent_runner` 抬升为可被自定义的 Protocol，并补上 logging / 错误信息 / 双语 README 这三块 v2 的可观测性短板。
